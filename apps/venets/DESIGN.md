# ВЕНЕЦ — компактная продуктовая спецификация

## Обещание игроку
Браузерная династическая стратегия для телефона и ПК: небольшая, но автономная средневековая политическая система; игрок управляет *династией*, не напрямую государством. Решение меняет мир, другие агенты реагируют, последствия сохраняются между поколениями. Проигрыш титула может породить новую кампанию.

## Пять неснимаемых столпов
1. **Агентность:** как минимум два жизнеспособных подхода к ключевому конфликту.
2. **Автономный мир:** персонажи преследуют собственные цели и действуют без вмешательства игрока.
3. **Связанные системы:** брак/родство ↔ наследование ↔ титулы/вассалы ↔ война/дипломатия.
4. **Долгосрочная память:** обиды, услуги, претензии, союзы, смерти и история титулов.
5. **Понятная причинность:** игрок способен объяснить, почему произошли мятеж, наследование и политическое решение.

## Гипотетический целевой масштаб (не установленный оптимум)
- 48 провинций, 10–14 владений верхнего уровня, 120–180 активных персонажей, типичная партия 3–5 поколений.
- В первом модельном прототипе **12 провинций** и только необходимые персонажи. Числа меняются по измерениям, а не по эстетическому вкусу.

## Первый симуляционный срез
- Entity: Person(id, age, traits, memories, goals, relationships, kinship, rights, resources).
- Title(id, rank, owner, liege, jurisdiction, successionLaw, claimants).
- Province(id, title, terrain, settlement, economy), Dynasty(id, members, prestige), PoliticalAction(id, actor, targets, preconditions, costs, effects).
- Движок использует детерминированный PRNG и порядок событий; сохранение/загрузка полных снимков мира; журнал причин.
- ИИ: доступные действия → расчёт полезности с учётом целей/риска/характера → выбор → последствия. Без сетевой LLM.
- Брак, рождение/смерть, раздел наследства, претензии, пожалование титула, вассальное недовольство, заговор, война/мир — первый взаимосвязанный набор.
- Война стратегическая, а не tactical RTS: сбор войск, командование, крепости, снабжение, политические результаты.
- События — проявления состояния мира, а не генератор случайных карточек, отменяющий симуляцию.

## Главный сценарий будущей игры
Старт графом → действия через персонажей и владения → развитие политических конфликтов → наследование → последствия при следующем правителе. Содержательная партия должна порождать собственные истории без заскриптованной цепочки событий.

## Mobile/desktop
Общие правила симуляции; отличаются плотность данных и расположение панели. Focus-first: карта/ситуация на основном пространстве, одно контекстное действие, глубина по запросу; без лишнего вертикального скролла, без обязательного hover. Скорость времени при важных событиях приостанавливается. Всегда доступен возврат в PocketWorks.

## Архитектура будущей игры
Отдельные модули simulation / AI / persistence / event-log / renderer / UI / tests. TypeScript или JS; карта Canvas 2D/WebGL, интерфейс DOM/SVG; расчёты возможно в Worker; IndexedDB для сохранений. Всё offline-first, в пределах apps/venets. Никакой замены оболочки PocketWorks.

## Не делать в первом релизе
Мировую карту, тысячи персонажей, 3D-портретные анимации, тактическую военную RTS, десятки ресурсов, сложную экономику домохозяйств, сетевой мультиплеер, события без последствий, бессодержательную анимацию, дублирующиеся панели.
