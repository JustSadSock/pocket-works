# FORMA 2.0 — OpenSCAD + функциональный контракт

## Зачем снова изменён подход

`FormaBlueprint 1` оказался слишком узким. Нейронка выбирала несколько библиотечных типов, а приложение додумывала остальную конструкцию. Формально валидный Blueprint мог содержать «дифференциал», который на деле был коробкой, два соосных диска вместо независимых выходов или передаточное отношение с перепутанным направлением.

FORMA 2.0 разделяет две независимые вещи:

1. **Геометрия** — настоящий OpenSCAD-код.
2. **Функция** — отдельный контракт, который приложение рассчитывает и проверяет.

Красивый рендер больше не считается доказательством работы. Если задача заявляет ускорение 1:5, FORMA должна вычислить `|ωout / ωin| = 5`. Если это невозможно, экспорт блокируется.

## Предпочтительный формат — один `.scad` файл

Файл начинается с JSON-метаданных внутри комментария, затем содержит обычный OpenSCAD-код:

```scad
/* FORMA_PROJECT
{
  "name": "Planetary Accelerator 5x",
  "settings": { "detail": 56, "margin": 2 },
  "parts": [
    {
      "id": "sun",
      "name": "Output sun",
      "color": "#e07043",
      "entry": "sun",
      "mechanics": { "kind": "gear", "teeth": 12, "module": 1 }
    }
  ],
  "contract": {
    "mode": "mechanical",
    "joints": [],
    "objectives": []
  }
}
*/

module sun() {
  forma_spur_gear(teeth=12, module=1, thickness=5, bore=3.2);
}
```

`parts[].entry` указывает имя OpenSCAD-модуля, который строит конкретную печатную деталь. Каждая физически отдельная или отдельно окрашенная деталь должна иметь собственный `id` и собственный модуль.

JSON-конверт `forma-cad-project-1` тоже поддерживается для API и программной генерации, но для общения с нейронкой `.scad` удобнее: код не нужно экранировать внутри строки JSON.

## Поддерживаемый OpenSCAD-профиль

FORMA исполняет строгий совместимый профиль:

- `module`, переменные, арифметика, массивы и диапазоны;
- `for`, `if`;
- `cube`, `sphere`, `cylinder`, `polygon`;
- `translate`, `rotate`, `scale`, `mirror`, `color`;
- `union`, `difference`, `intersection`;
- `linear_extrude`, `rotate_extrude`.

Пока намеренно отклоняются `hull`, `minkowski`, `text`, `import`, `surface`, `projection`, `polyhedron`, `children` и внешние библиотеки. Приложение выдаёт точную строку и столбец вместо молчаливого приблизительного результата.

## Сертифицированные механические модули

Обычная геометрия может быть любой в пределах профиля. Но механические утверждения принимаются только для геометрии, параметры которой приложение может сопоставить с контрактом:

```scad
forma_spur_gear(
  teeth=40,
  module=1,
  thickness=5,
  bore=3.2,
  backlash=0.18
);

forma_ring_gear(
  teeth=48,
  module=1,
  thickness=5,
  wall=3,
  backlash=0.18
);

forma_planet_carrier(
  orbit=15,
  count=1,
  plate_thickness=3,
  pin_diameter=3,
  pin_height=5,
  bore=3.2,
  plate_radius=20
);
```

Это не декоративные шаблоны вместо CAD. Это проверяемые библиотечные модули внутри стандартного OpenSCAD-кода. Их можно свободно размещать и комбинировать, а FORMA считывает фактические координаты после `translate`, `rotate`, `scale` и `mirror`.

## Контракт механики

Статическая модель использует:

```json
{"mode":"static","joints":[],"objectives":[]}
```

Механизм использует `mode: "mechanical"` и обязан иметь связи и цели.

### Связи

```json
{"type":"fixed","part":"ring"}
{"type":"revolute","part":"driver","axis":"z"}
{"type":"gearMesh","a":"driver","b":"output","clearance":0}
{"type":"coaxial","parts":["sun","ring","carrier"]}
{"type":"contains","housing":"case","parts":["driver","output"]}
{"type":"planetary","sun":"sun","ring":"ring","carrier":"carrier","planets":["planet"],"teeth":{"sun":12,"planet":18,"ring":48},"module":1}
```

### Проверяемые цели

```json
{"type":"fixedPart","part":"ring"}
{"type":"speedRatio","input":"carrier","output":"sun","ratio":5,"direction":"increase","tolerance":0.01}
{"type":"partCount","value":4}
{"type":"noExternalHardware"}
```

`speedRatio` всегда означает модуль отношения угловых скоростей:

`abs(output speed / input speed)`.

- `direction: "increase"` — выход обязан вращаться быстрее входа.
- `direction: "reduction"` — выход обязан вращаться медленнее.
- Знак рассчитанного отношения отдельно показывает одинаковое или обратное направление вращения.

## Что FORMA реально проверяет

Для обычной пары шестерён:

- обе детали построены сертифицированным модулем;
- числа зубьев и модуль в коде совпадают с `parts[].mechanics`;
- оси параллельны;
- фактическое межосевое расстояние из OpenSCAD-трансформаций совпадает с расчётным;
- вход и выход соединены непрерывной цепью;
- итоговое отношение и его смысл `increase/reduction` совпадают с целью.

Для планетарного комплекта:

- `ring = sun + 2 × planet`;
- солнце и кольцо соосны;
- планета стоит на рассчитанном радиусе;
- водило имеет тот же радиус пальцев и правильное их количество;
- один из трёх членов реально зафиксирован;
- отношение вычисляется из уравнения планетарного ряда.

## Дифференциал

Настоящий дифференциал требует двух независимых выходов и отдельной проверяемой кинематики. В FORMA 2.0 сертифицированного генератора конического или полноценного планетарного дифференциала ещё нет.

Поэтому приложение **обязано отклонять** `differential`, а не заменять его:

- коробкой `custom`;
- двумя соосными дисками;
- декоративными шестернями;
- обычной планетаркой с одним выходом.

Это сознательное ограничение. Честная блокировка полезнее печатного механического гороскопа.

## Repair-пакет

При ошибке FORMA создаёт пакет с:

- кодом ошибки;
- объяснением;
- конкретным исправлением;
- исходным CAD-файлом;
- правилами, которые нельзя нарушать при повторной генерации.

Отправьте пакет нейронке целиком и попросите вернуть один исправленный `.scad` файл без Markdown.

## Мастер-промт

Используйте встроенную кнопку «Комплект для AI». Она копирует актуальный промт и запрещает нейронке:

- выдумывать неподдерживаемую механику;
- оставлять заглушки;
- путать ускорение с редукцией;
- объявлять связь без соответствующей геометрии;
- использовать неподдерживаемые команды OpenSCAD.
