# Дорожная карта «БОЖЕ, НЕ ТАК!»

Обновлено 2026-10-17. Версии обозначают **объем работ, а не даты**. Каждая стадия требует рабочий вертикальный сценарий, тестирование и отдельную фиксацию результата. Не смешивать новые функции с непройденными регрессиями.

## P0 · v0.1.0 · Проектное досье — завершено
- Записать концепцию, MVP и границы проекта.
- Зафиксировать проверенные лимиты PocketNet и отложенные инфраструктурные изменения.
- Сформировать игровую модель, art direction, тест-матрицу и критерии приемки.
- Зарегистрировать отдельное экспериментальное приложение-досье в каталоге Pocket Works.
- **Готово, если:** план открывается на телефоне, имеет рабочую навигацию и офлайн-копию, docs в директории приложения, нет притворного онлайн-матча.

## P1 · v0.2.0 · Честный игровой вертикальный срез — реализовано
- Полностью локальный проход: знамение → подготовка → сборка → решение бога → один догмат → следующий обряд → результат.
- 1 бог, 6 видов пророчеств, 10 предметов, 4 чудесных визуальных эффекта, 8 действующих догматов.
- 5 связанных раундов, локальный генератор с seed, идентичный результат при одинаковой последовательности действий.
- Удобное управление одним пальцем; без постоянного вертикального скролла.
- **Готово, если:** завершены 5 раундов, поражение/победа объяснимы, нет пустого экрана или фиктивной кнопки; восстановление после reload; тесты ≥ 30 детерминированных прогонов.

### Реализация P1
В коде: `engine.js` (детерминированный расчёт, ритуалы, догматы, вера), `art.js` (авторские SVG), `app.js` (рабочая локальная партия и сохранение), `tests/ritual.test.mjs` и `qa/playthrough.mjs` (модель и настоящий браузерный сценарий). Фаза P1 завершается **только после успешных автоматических и визуальных проверок**, код сам по себе не является доказательством приёмки.

## P2 · v0.3.0 · PocketNet и безопасные комнаты — реализовано
- Новые комнаты 2–5, коды приглашений, reconnect и server-authoritative результат.
- Реализовать модуль `server/module.ts` с действиями-id, ревизиями, фазами, событиями и дедлайнами.
- **Блокер приватности:** существующий `room_joined` возвращает полный `room.state`. Секретные сведения НЕЛЬЗЯ помещать в передаваемое состояние до отдельного совместимого platform PR, реализующего безопасную выдачу view для комнаты. Без этого P2 запускается только с публичными данными.
- Platform PR (если нужен) оформляется отдельно от app PR по `AGENTS.md`; immutable snapshot модуля и lock публиковать по текущему workflow.
- **Готово, если:** 2, 3, 5 реальных клиента играют полный матч, повторная команда не меняет результат, reconnect сохранил подтверждения, ни один клиент не получает скрытое состояние других.

### Фактическая реализация P2 (v0.3)
Комнаты 2–5 игроков, код/ссылка, авторитетный сервер `server/module.ts`, pin `pocketnet/module-versions/bozhe-ne-tak/v1.ts`, выбор и блокировка собственного подношения, командный приговор, голосование, серверные дедлайны, восстановление комнаты после reconnect. **Секретной информации в state нет** до отдельного исправления платформы. UI использует `online.js`, прежний локальный режим сохранён. Проверки: `tests/server.test.mjs`, браузерная матрица, PocketNet Edge и Pocket Server modules.

## P3 · v0.4.0 · Настоящая кооперация без голосового чата
- 3 асимметричные роли: Пророк, Ризничий, Звонарь. На 2 игроках совмещать обязанности; 4–5 — параллельные ответственные места.
- Структурированные сообщения: предмет + оценка, запрос, согласие, предупреждение, указатель. Необходимые для прохождения подсказки доступны без внешнего голоса.
- Закрепить роли на один обряд, менять в следующем; каждый игрок занят в ≥ 80% раундов по тестовым сценариям.
- **Готово, если:** группа из 3 устройств завершает матч без голоса и свободного чата, без ситуации, когда один игрок механически выполняет все действия.

## P4 · v0.5.0 · Догматы, чудеса, реиграбельность
- Накопление догматов как исполняемых модификаторов правил; связь с историей партии.
- 3 бога с отличающимися предпочтениями и реакциями, 20 предметов, ≥ 20 догматов, ≥ 12 архетипов задач.
- Конфликты догматов разрешаются через валидацию/замену, **никогда не создают неразрешимых ситуаций**; возможность «собора» пересмотреть один догмат с ценой.
- **Готово, если:** массовые seeded-симуляции не обнаруживают тупиков, существует ≥ 3 отличающиеся стратегии выполнения обрядов.

## Приоритет реализации
Блокирующие цепочки: безопасность приватного state → асимметричная информация; рабочий локальный цикл → сетевое расширение; детерминированные seeded правила → генерация догматов; финальная графика → только после доказанного игрового ядра. Не начинать с 3D, голосового чата, персистентного мира или генеративной LLM в рантайме.
