# QA и модельные тесты

## P0 — досье
1. `npm run registry:check`: app.config, id/cache/slug уникальны.
2. Открытие iPhone portrait и desktop: сразу видна текущая стадия и активное действие; нет обрезки; работает навигация разделов и переход в PocketWorks.
3. Осмысленная навигация: выбрать каждую стадию, открыть критерии и зависимости; переход назад; обновление страницы не ломает состояние.
4. Offline после первого открытия, Service Worker не забирает чужой cache; звук/голос/онлайн режим не обещаются.
5. Visual QA screenshot review, console errors и реальный WebKit — перед маркировкой законченного релиза.

## P1 — детерминированная игровая модель
- Property-based тест `resolve(seed, actions, dogmas)`: одинаковый вход дает одинаковый результат, независимо от браузера.
- Генерация 1000 seed × наборы догматов; ни один раунд не создается без решения.
- 30 локальных 5-раундовых матчей, 3 победы, 3 поражения, смена правил, восстановление из localStorage.
- Покрыть пустые подношения, неверный предмет, чужую роль, отсутствие реакции, преждевременную отмену, повторный тап, состояние на deadline.
- Не создавать fake control или «святое» действие, которое ничего не меняет.

## P2–P4 — транспорт / безопасность
- 2/3/5 устройств/браузерных вкладок, минимум по 10 полных матчей на каждый размер группы.
- `actionId` дубликат 2–5 раз дает один эффект; старый `phaseId` отклоняется; baseRevision гонки разрешаются детерминированно.
- Полное разделение секретов: инспекция room_joined, sync, events, local storage, переподключение, fallback packet. Незнание подписи в UI не является защитой.
- Сверка клиентов на каждой фазе: у всех одинаковые оценки, догматы, хронология и итог, кроме разрешенной приватной информации.
- Разрыв соединения на 1/5/20 сек; перезапуск Worker; переключение приложения в фон; local clock отличается ±10 сек; устройство теряет сеть на дедлайне.
- Тайминг 150/300/600ms RTT, 3% потерь и пакет из 5 одновременных действий. Успех означает отсутствие потерянного или двойного подтвержденного действия.

## Метрики
Собирать не персональные сведения, а суммарные значения: messages per match, avg payload, p50/p95 ack latency, bytes persisted, DO write operations, reconnect recovery time, error counts, unfinishable seed count. Никаких ложно точных «тиков». Пороги P6: 50 полных сетевых матчей без несходимости и тупиков; p95 ack измерить и сравнить с UX целями, лимиты Free Cloudflare не превышены в тестовом профиле.

## Арт и доступность
WebKit/Chromium mobile 320px/390px и desktop 1365px. Screen recording start/action/result, screenshot review. VoiceOver labels, keyboard navigation, 44px touch, safe areas, reduced-motion, звук отключается, отсутствие горизонтального скролла. Нет тяжёлого рендеринга в скрытой вкладке.

## Правила выпуска
Нет доказательства тестов — стадия не закрывается. Нельзя назвать P2 «кооперативом», пока нет хотя бы одного полного онлайн матча на нескольких реальных клиентах. Не путать сетевую активность браузера с получением серверного подтверждения.

## V0.3 — проверка конкретного PocketNet модуля
- `tests/server.test.mjs`: 2/3/5 участников, один настоятель, join до старта, запрет join mid-match, каждая ячейка принадлежит своему игроку.
- Дубликат `seq` и прошлый `phaseId` не применяются повторно.
- Сквозная серия из пяти обрядов, персональные оценки и среднее команды, догмат большинства.
- Дедлайн при отсутствии игрока: fallback хлеба, переход в суд, собрание, новый раунд.
- Reconnect snapshot: ревизии, последний `seq`, права настоятеля после явного ухода; WebSocket отключение не равно уходу.
- Проверка отсутствия секретов в публичном `room_joined`: пока запрещены индивидуальные пророчества и приватные сообщения.
- Edge/WebSocket CI и браузерная проверка страницы комнаты с реальным UI обязательны; generic Playwright не доказывает подключение к реальному Cloudflare без Edge.
- Настоящие массовые latency tests после релиза: отдельно измерить p50/p95 обработки 5 одновременных даров и write budget; не утверждать не измеренные миллисекунды.

## V0.4 — закрытый протокол
- Все пять обязанностей назначены ровно одному из 2–5 участников; при каждом новом обряде задачи ротируются.
- Секреты в приватном объекте: no seed, no future order, no full riddle, no чужие подсказки. Сравнить `viewForPlayer` всех участников.
- Злой клиент не может выполнять чужую роль, подделывать текст знамений, присылать неизвестные вещи, пинговать произвольным HTML, повторять seq, применять старый phaseId.
- Полная серверная партия 2/3/4/5 на пяти раундах, голосование, получение догматов, отсутствие потери записей, сохранение.
- Когда кто-то пропал или не выполнил роль, серверный timeout присваивает стандартное действие и разрешает суд.
- Два живых браузерных клиента: раскрыл собственное знамение, другой назначил звон/высоту, общий суд, собор, обновление страницы и восстановление скрытой роли.
- Приватность протокола также проверить Edge интеграционно: `room_joined`, broadcast state, targeted sync, reconnect не должны содержать raw seed/order или чужие clue.
