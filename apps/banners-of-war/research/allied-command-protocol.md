# Allied Command — authority protocol, not yet public
The roster module is intentionally not routed from BannersMatchRoom until per-member information views/replay capture, room persistence, identity-bound invitations, real browser interface, and 2–4-client integration checks are complete. It is an executable domain layer, not a playable feature. It uses immutable banners-engine-v1 and its order validation. Existing duel state and routes are untouched.

Formats reserve 2vAI, 2v1, 2v2 and 3vAI seats. A captain owns the undelegated regiments; subordinates hold disjoint subtrees of the established four-level hierarchy. Ancestor orders spanning another player's scope are rejected rather than resolved by arrival order. General intent can be communicated separately as a typed marker. A captain may reassign a subtree or transfer leadership only before sealing; outstanding drafts on the side are invalidated. Explicit AI delegation is restricted to the captain and applies the same order validator. A deadline can seal latest drafts for disconnected users. Historical markers are directed; no remote battle observation is synthesized. In standard rooms, shared markers are supported by the model, but initial assignment requires an actual hierarchy; standard room adapter is not complete.

The current tests use real v1 historical scenario states, exercise all four seat formats, validate scope and replay/round transition, and execute a combined historical-command round. They do not prove network security or reconnect behaviour for Allied Command. Future room integration must use opaque seat IDs, bind actors to Pocket ID server-side, persist authority changes atomically and version per-player frame visibility; no reuse of side-wide replay for subordinate clients without a disclosure review.

## Integrated candidate (protocol 1)
The existing BannersMatchRoom now dispatches allied matches through banners-allied-room.mjs, without changing duel state, paths, physics or engine identifier. Seat identity is bound to Pocket ID; external actions refer to opaque seat indices and authority revision. The existing per-room serial queue and SQLite transaction commit state, full round and member-specific historical frame rows atomically. A non-historical team uses the side-wide fog projection; historical subordinate views use assigned units and local sight, captain additionally sees the original HQ reports. Historical player-authored markers are addressed and delivered on the next planning round; they carry no server-derived enemy coordinates. Personal replay rows are keyed by stable seat, not current group ownership. Finished reveal respects room rules. Authority reassignment is blocked if the side has saved orders, and sealed orders cannot be revoked; deadline retains latest saved drafts and does not remove a disconnected user's seat. Explicit AI delegation does not create new identities. The 60-unit cap remains unchanged. A rematch opens a fresh room with the same format and scenario, not inherited assignments. UI includes compact roster, map scope, allocation/handoff, direct coordination and optional local-only playtest export. Historical planner remains the pinned report-driven engine; free team AI can choose legacy or Enemy Minds. Browser tests for all four formats and both mobile engines are added; do not claim playable release until CI confirms them.

Authority revisions are now side-specific during planning: opposing-side readiness/assignment changes never invalidate a local unsealed draft. Lobby changes still reset acceptance for all participants. Existing saved orders remain protected; the UI confirms discarding an unsaved local draft before changing authority.

## Final release browser gate
The previous browser matrix used one Pocket ID store for ten tests; its genuine six-registration rate limit stopped eight tests with HTTP 429 (run 45522488774). The new app-specific shell harness uses one local Wrangler instance with a fresh SQLite store and a distinct HTTPS port for every browser/format pair. It originally ran two cases at a time (superseded below), continues through every format even if a case fails, and requires exactly one clean test pass per case (no skipped/flaky successes). All ten reports, logs and screenshots have separate artifact paths. No Pocket ID limits, cookie handling, authorization or production configuration changed. The 2v2 test additionally checks authenticated non-member rejection, distinct personal replay feeds, and real recovery of the current captain in a new browser context.

### Worker isolation follow-up
Run 45524206911 passed WebKit duel, WebKit 2vAI, Chromium 2v1, WebKit 2v2 and WebKit 3vAI. The other five failed before launching Playwright with workerd's internal `direct:1:default` socket conflict. The matrix is now sequential. Every local Worker in this job is launched in a separate process session; teardown signals the whole process group, waits for live descendants and listener release, escalates to SIGKILL only if needed, and refuses to run the next case if cleanup is incomplete. The job timeout is 25 minutes to accommodate all ten sequential full scenarios. The ten stores, real HTTPS and account registration remain independent; no gameplay or production authorization code changed. A new clean 10/10 run is still required.
