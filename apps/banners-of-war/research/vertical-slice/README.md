# Greyford — Art of War vertical slice

This is an isolated evaluation route of the existing Banners of War app, not a replacement for the production UI. Start `index.html` on the app's served origin or save `standalone.html` and open it as a local file. The standalone is generated deterministically from the exact current engine and app modules via `node apps/banners-of-war/research/vertical-slice/build-slice.mjs`; Node QA checks byte equality. No external assets, requests or accounts are required. Existing app save namespace, networking and replay formats are untouched. Slice campaign history is in memory; closing/reloading the tab discards the evaluation session.

## Design
Living Historical Atlas + Miniature Battlefield: top-down orthographic, directional relief, continuous field, screen-sized heraldic flags, actual physical body sectors and cached original troop silhouettes. Fine elevation, woodland, wetland, river, ford, roads and settlements use the engine's actual geometry and samples; no imported assets. Miniatures are sampled visual representatives, never literal displayed headcounts. Motion interpolates genuine engine frames; per-rank small movement and disorder marks are visual representation, not separate agents. No changes to simulation, AI or damage. A contact layer is optional. This is 2.5D-style shaded top-down, not geometric 3D, and not a claim of a completed historical art direction.

## Commands
Tap a friendly regiment or group rail; tap an empty destination to draft movement, drag the center to edit the last position, rotate/frontage/depth handles are visible on selected groups. Right mouse or Route button draws a multi-point route; pan mode, pinch or middle mouse navigate without modifying orders. Box/lasso and Shift are available. Front tool lays regiments along a drawn line using physical dimensions; Hold adds brace after reaching a drafted front. Expand the dock for formation/conditions and stats. All existing conditions are available through actual engine stages; no new execution system. Undo/redo and warnings operate on drafts. Deployment is real and validated against oriented footprint overlaps, full deployment bounds and sampled water. Invalid changes are rejected atomically. Explicit submit confirms the actual 30-second WEGO calculation. Repeated rounds continue until engine declares result under the existing 360-second objective; events link to actual replay times. Open map is intentional for this evaluation; no Historical or Allied mode integration.

## Evaluation
Previous research baseline: 3 interactions group/front/drag; selected compact coverage 80.1% portrait, 86.6% desktop, 70.7% landscape for Atlas. New direct group/destination = 2 interactions by design; equivalent front remains 3. Do not treat action counts or automated milliseconds as human usability. New Playwright tests measure compact area, direct and front tasks, input-to-render latency, replay and full campaign; record screenshots and video. Render stress uses actual engine-created units at 20/60/100/158 in an explicitly synthetic spatial layout, actual resolved frames and 3 zooms, visible sprite counts, frame time/FPS/available JS heap and simulation timing. Canvas was retained for existing precision, cached terrain and efficient sprite draw/culling; no WebGL benchmark was run. Human visual signoff, physical device testing and production deployment remain separate.
