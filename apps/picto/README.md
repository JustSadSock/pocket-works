# ПИКТО — визуальный язык компании (v1.4.2)
Кооперативная онлайн-игра для 2–8 игроков в PocketWorks. Каждый по очереди создаёт без слов пиктографический рассказ из двух или трёх кадров; остальные независимо угадывают пять смысловых опор истории.

## Новые правила
- 70 **заранее связанных причинно-следственных историй** (28 строятся вокруг неочевидного мотива) в шести категориях вместо случайного выбора действия и предлога. Истории распределяются по раундам без повторения в одной партии.
- **112 уникальных знаков** (34 базовых + 78 дополнительных), категория и поиск по русскому названию; искусственные блокировки нужных символов отсутствуют.
- Свободная расстановка, поворот, масштабирование и перенос знаков на каждый кадр (до 48 в сообщении).
- Пять независимых ответов: кто, действие, объект, последствие, место. У предлогов нет разных синонимичных вариантов. Частичное угадывание остаётся справедливым: +2 за совпадение, −1 за ошибку, 0 за пропуск, минимум 0 за отправленный ответ.
- После раскрытия автор может сохранить собственную визуальную композицию в **словарь компании**. Словарь доступен всей комнате; ведущий сохраняет его локально в браузере и автоматически восстанавливает в следующей комнате. Автор может загрузить ранее сохранённую композицию как основу.
- Результаты и галерея показывают кадры по порядку.

## Совместимость
PocketNet snapshot `v6` применяется только к новым комнатам; предыдущие версии остаются неизменными. Клиент восстанавливает состояние также в комнатах `v5` при отклонённой запоздалой отправке. Клиент по-прежнему поддерживает классическую расшифровку из четырёх вариантов и схему предыдущей версии.

## Проверка
```bash
node --check apps/picto/app.js
node --check apps/picto/symbols.js
node --check apps/picto/sw.js
node --experimental-strip-types apps/picto/qa/rules.mjs
npm run registry:check
node scripts/build-pocketnet-modules.mjs --check
```
Проверить на реальных устройствах комнату из 2–8 игроков, кадры, поиск, отправку, частичные ответы, перезаход, сохранённый словарь, перенос панели инструментов на узком экране и старую комнату v3.

## Синхронизация и сцены (v5)
- Все устройства показывают один серверный дедлайн с регулярной коррекцией смещения часов. Клиентская дата больше не определяет переход фазы.
- Автор текущего раунда публикует окончательный массив знаков атомарно одной командой, независимо от создателя комнаты.
- Один заполненный кадр допустим; пустой дополнительный кадр намеренно остаётся пустым. Полностью пустой авторский ход пропускает угадывание по тайм-ауту.
- Черновик авторской композиции сохраняется в sessionStorage для восстановления после сетевого обрыва.
- Все кадры, результаты и превью имеют единое соотношение 3:2; пиктограммы масштабируются пропорционально холсту, а координаты задаются процентами.
- Библиотека пиктограмм содержит контекстные многозначные подсказки, которые доступны через поиск и подписи.
- Новые комнаты закрепляются за snapshot v5; ранее созданные v4 и v3 сохраняют свои правила.

## Регрессионные проверки
Тесты в `qa/rules.mjs` проверяют передачу авторства по всем игрокам, частичные ответы, пустой второй кадр, отправку последней версии доски одной командой, синхронизацию времени и истечение таймера с пустой композицией.

## Исправление дедлайна (v6, клиент 1.4.1)
- Любая команда (включая запоздалую публикацию) может вызвать серверный переход фазы, и он рассылается **всем** участникам.
- Запоздалая публикация и действия неактуального автора возвращают свежее состояние вместо одного уведомления; автор больше не застревает с таймером 00:00.
- Клиент дополнительно перепроверяет состояние при нулевом таймере и после характерной ошибки старого PocketNet v5. Уже созданные комнаты не переводятся на новый snapshot автоматически.
- В `qa/rules.mjs` и `qa/online-flow.mjs` добавлена регрессия для публикации сразу после истечения времени.

## Регрессии 1.4.2
- Проверены в браузерном сценарии комнаты v6 и ранее закреплённые v5, включая восстановление обеих сторон после молчаливого дедлайна, перезаход с черновиком, три игрока, частичные ответы и трёхкадровый раунд.
- Клиент на 00:00 отправляет полный `sync`, а не `pulse`: старый сервер может навсегда вернуть только время после пропущенного перехода.
- Скриншоты собираются из автоматизированных браузерных прогонов для телефонного, планшетного и десктопного экранов.
