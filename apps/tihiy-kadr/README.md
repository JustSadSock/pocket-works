# Тихий кадр — локальное удаление речи и сравнение методов (v1.3.0)

## Обычное использование — без других сайтов

1. Выберите видео и фрагмент.
2. Выберите **«Быстро · MRX»** или **«Дополнительно · MRX + SCNet»**.
3. Нажмите **«Убрать речь»**. В первом варианте запускается один проверенный MRX ONNX. Во втором — две настоящие нейросети последовательно: MRX отделяет речь/музыку/эффекты, SCNet пытается выделить оставшийся вокал в фоне M&E.
4. Сравните версии в готовом видеоплеере. SCNet регулируется от 0 до 100% без дополнительного инференса.
5. Сохраните WAV или обработанное видео.

Дополнительный проход SCNet весит 12.9 MB (MIT), загружается через фиксированный серверный список PocketWorks. Вычисления идут в локальном WASM; это может быть медленнее исходной MRX. SCNet обучена на музыкальном разделении и **не гарантирует** устранения голоса Мэйбл или других диалогов без ущерба для эффектов.

**Никаких внешних сайтов, ключей, экспорта/импорта WAV для основного сценария.**

## Почему прежняя инструкция с 5.1 была ошибочной

Кнопка скачивания исходного WAV из браузера сохраняет двухканальный стереомикс. Его невозможно загрузить в проверку 5.1, потому что она требует независимые 6 (5.1) или 8 (7.1) каналов исходного файла. Приложение определяет настоящие каналы при декодировании, если браузер их предоставляет. Ручная загрузка шестиканального WAV — исключительно исследовательская опция.


## Цель

Сравнить фактическую скорость, остатки речи и сохранность музыки/эффектов для одной и той же сцены. **Объективные метрики уровня не равны качеству удаления речи.** Сравнение на Диппере и Мэйбл требует настоящих мультяшных фрагментов и субъективного прослушивания. Эту лабораторию нельзя считать доказательством качества модели без референсного набора.

## Сейчас работают

1. **MRX / ONNX Runtime WASM** — локальная сеть только для загрузки библиотеки и весов, исходное аудио остаётся на устройстве. Встроенные 0–90 с фрагменты (1–90 с).
2. **5.1/7.1** — независимое удаление центрального канала в многоканальном PCM WAV без нейросети. Поддерживает PCM16/24/32 и float32, в том числе WAVE_FORMAT_EXTENSIBLE. Из оригинального видео, если его аудиодекодер отдаёт 6/8 независимых каналов, результат появляется автоматически. Иначе можно отдельно выбрать многоканальный WAV, подготовленный FFmpeg на ПК. Например:
   ```bash
   ffmpeg -i "source.mkv" -map 0:a:0 -vn -c:a pcm_s24le "soundtrack-5.1.wav"
   ```
   Сохранение 5.1/7.1 зависит от декодера и реального канального формата оригинала. Если файл стерео, этот метод недоступен.
3. **MVSep DnR v3 SCNet / Ensemble, BandIt v2, SAM Audio и любая другая модель** — реальный импорт уже обработанного M&E или отдельных дорожек Music+Effects. Автоматического запуска этих тяжёлых движков нет. Приложение **не** отправляет исходный файл на MVSep, не хранит API ключи и не симулирует результаты.
4. **Сравнение** — общий видеоотрезок, A/B-переключение, воспроизведение, скачивание WAV/видео и CSV-замеров. Для удалённой модели время вводится вручную, только если действительно измерено. В статистике RMS, пик, изменённая часть и real-time factor; не выдумываем SDR.

## Как повторить сравнение DnR v3

1. Выбрать исходное видео и конкретный участок 5–10 секунд с высокой женской/детской речью, несколькими согласными, отдельным эффектом и фоновым сопровождением.
2. «Скачать исходный звук WAV».
3. Отправить этот WAV в официальный [MVSep](https://mvsep.com/en). У MVSep API требуется **личный API-токен**, поэтому лаборатория не отправляет файл автоматически.
4. Выбрать **MVSep DnR v3, SCNet Large** (API sep_type=56, add_opt1=0); затем **Mel + SCNet** (sep_type=56, add_opt1=2); **BandIt v2** (sep_type=45). Для SAM Audio требуется отдельно полученный доступ к контрольным весам и GPU.
5. Скачать результат Music+Effects или две дорожки Music и Effects. В лаборатории выбрать метод, загрузить соответствующие файлы и нажать «Добавить результат к сравнению».
6. Прослушать на одном времени. Обязательно проверить: не остался ли голос Мэйбл; слышны ли шаги, щелчки, удары, музыка; сколько времени заняло получение результата. Затем экспортировать CSV с теми же сценами.

Оценку скорости проводить **отдельно** для скачивания весов, инференса, очереди и ремультиплексирования. Для 5.1 время канального сведения измеряется отдельно. На практике дополнительно есть время чтения исходного файла, декодирования и экспорта.

## Справочник кандидатов

| Направление | Статус | Следующая проверка |
|---|---|---|
| MRX | Проверено браузерным CI, качество на Gravity Falls неудовлетворительно | Сравнить против сцены с Мэйбл |
| Прямое 5.1/7.1 | Реализовано и проверено на синтетическом канальном WAV | Найти исходную дорожку именно 5.1 |
| DnR v3 SCNet | Принимаются реальные результаты | Замер на одинаковом мультфильме, API-токен не хранить |
| DnR v3 ensemble | Принимаются реальные результаты | Сравнить скорость очереди / качество |
| BandIt v2 | Принимаются реальные результаты | Проверить лицензию весов и скорость на GPU |
| SAM Audio | Принимается реальная residual-дорожка | Запросить официальный доступ к весам, проверить VRAM |
| TIGER в браузере CPU | Отклонено по времени: предыдущий CI не закончил 1 с за 180 с | Пробовать только при пригодном GPU |
| LiteCASS | Исследовательская публикация; готовый официальный конвейер весов не подтверждён | Найти открытые веса и репозиторий, пока кнопку не добавлять |
| Две синхронные озвучки | Теоретическая гипотеза | Искать источники с одинаковым мастером, выровнять кадры |

Лицензии весов отличаются от лицензий кода. Для публичного использования PocketWorks проверить каждую модель до встраивания.

## Архитектура

- `research-core.js`: pure PCM adapter, RIFF WAV parser, 5.1/7.1 downmix, метрики (тестируются Node).
- `app.js`: пользовательские действия и результаты отдельных методов, связаны с **одним** видеоплеером и экспортом.
- `mrx-worker.js`: реальная нейросеть MRX / ONNX без передачи звуковой дорожки на внешний сервер.
- `pocketnet/mrx-assets.mjs`: строго ограниченная серверная доставка публичных весов и ONNX wasm.

Статистика и PCM результатов остаются в памяти вкладки. Для воспроизводимого протокола экспортируйте CSV и звуковые дорожки. При переходе на другой исходный файл набор сравнения сбрасывается, чтобы результаты разных сцен не смешивались.

## Что пока не решено

- API DnR v3 / BandIt требует ключа; автоматическую загрузку в облако без разрешения пользователя не реализовывали.
- Локальные GPU-модели требуют отдельного исполнителя, проверки лицензий и измерений на RTX 3080.
- Некоторые браузеры декодируют оригинальный 5.1 в обычное стерео. В таком случае загрузите отдельный WAV без downmix.
- Сравнение RMS не определяет, сколько диалогов осталось: для объективного SDR нужны истинные выделенные речь/музыка/эффекты.
