## Надёжность записи и уровень нейроочищенного фона · v1.14.2

## Контрольная сцена перед комнатой · v1.14.1

Подготовка видео теперь состоит из **трёх самостоятельных этапов**: выбор отрывка → выбор звука → предпросмотр и подтверждение. Завершение Open-Unmix, гибридной SCNet, полной SCNet или экспорта немого/исходного звука **не** запускает комнату. Видеоплеер показывает готовый вариант; сравнение с оригиналом сохраняет приблизительную позицию воспроизведения.

На контрольной доступны возврат к моделям и настройкам, создание полностью немой версии и возврат оригинальной звуковой дорожки. Исходный файл сохраняется отдельно до окончательного подтверждения; параметры обработки могут меняться без перезапуска выбора видео. Переход к комнате происходит только после явного «Подтвердить и продолжить». При выборе нового файла выводится подтверждение, а из каталога можно вернуться к текущему предпросмотру, не заменив файл. Кнопка комнаты указывает, что **заменяет**, а не впервые выбирает видео.

## Двухэтапная подготовка сцены · v1.14.0

**Шаг 1 — отрывок.** Сначала выбирается фрагмент видеозаписи от 10 до 90 секунд на интерактивной шкале с двумя ручками. На этом этапе нет запуска ONNX, аудио не обрабатывается, оригинальное видео остаётся нетронутым.

**Шаг 2 — звук.** Фиксируется выбранный таймкод, после чего предлагается ровно три варианта:

1. **Убрать голоса нейросетью** (стандарт): Open-Unmix / Open-Unmix + точечная SCNet / SCNet полностью. Работа выполняется только над ранее выделенным фрагментом, а фоновая музыка и эффекты сохраняются настолько, насколько позволяет сепарация.
2. **Убрать весь звук**: видеокодировщик создаёт полностью немой отрывок, без загрузки моделей. Редактор и премьера не ожидают музыкального сопровождения.
3. **Оставить исходный звук**: видео обрезается без нейросети; для встроенного удалённого видео может использоваться исходный файл с временными границами без повторного кодирования.

Пользователь может вернуться к выбору границ, сравнить исходник и результат, выбрать качество и разрешение видео перед экспортом, отменить длительную обработку. При смене звукового режима готовое видео сбрасывается: некорректный результат из другого режима не используется. В комнату и премьеру идёт только выбранный обработанный отрывок, участникам не нужно запускать ONNX. Никакие шаги не скрывают исходную длительность и приблизительные сроки.

## Аудиоподготовка для старых компьютеров · 1.13.1

**Что исправлено**

- Теперь на Chromium с WebCodecs приложение пытается читать только AAC-аудиодорожку MP4/MOV напрямую из сжатых пакетов (таблицы MP4), не открывая весь файл в оперативной памяти и не проигрывая видеокадры. Для необычных MP4/MOV, WebM и иных неподдерживаемых аудиокодеков остаётся ограниченный по размеру `decodeAudioData` и затем резервный захват в реальном времени. По этой причине не каждый файл станет быстрым.
- Для памяти: Web Workers получают аудиобуферы с передачей владения через Transferable, а не с повторным копированием десятков мегабайт. Спектральный фильтр обрабатывает их в отдельном Worker и повторно использует PCM.
- Для устройств с `deviceMemory<=4` ГиБ либо `hardwareConcurrency<=4` автоматически включается «Защита памяти»: нейросеть обрабатывает короткие окна ~8 секунд последовательно, а финальное видео по умолчанию ограничивается шириной 640 px и уровнем качества 3. Это может увеличить длительность обработки, но ограничивает пиковую нагрузку. Пользователь может выбрать эту опцию вручную.
- Оценка на экране больше не выдаёт 5 секунд Open-Unmix за общее время подготовки. Учтены стадии аудио и кодирования. Измеренная скорость моделей сохраняется в локальных настройках браузера для последующих оценок.

**Важно:** экспорту MP4/WebM на базе текущего `MediaRecorder` по-прежнему требуется проигрывание сцены для переноса кадров, обычно не меньше длительности выбранного видео. Ускорение этой стадии потребует отдельного ремультиплексора/кодировщика, а не только изменения ONNX. Ошибка STATUS_BREAKPOINT является крахом процесса Chrome, поэтому восстановить ту же вкладку без перезапуска после такого сбоя нельзя; уменьшение нагрузки и отказ от лишних буферов предупреждают наиболее вероятный сценарий, но не гарантируют отсутствие иных проблем видеодрайвера/браузера.

## Удаление оригинальных диалогов · 1.13.0

Переход от проверенной экспериментальной лаборатории «Тихий кадр» к настоящему игровому процессу. При выборе сцены и подтверждении перед стартом комнаты по умолчанию запускается **Open-Unmix**, в альтернативных режимах — Open-Unmix с точечной SCNet либо **SCNet на всём выбранном отрезке**. Пользователь видит приблизительное время **только нейросетей** и коэффициент относительно быстрого варианта (в основе замеры Open-Unmix ~5 с, SCNet ~150 с на 90 с тестового видео на ПК). Упаковка видео с новой звуковой дорожкой занимает дополнительно примерно реальную длительность сцены; извлечение аудио тоже может потребовать реального времени на устройствах без быстрого декодирования.

Модели выполняются локально в браузерных ONNX Web Workers, повторно используются проверенные файлы «Тихого кадра». Выбранные проблемные участки для гибрида определяются по vocal stem Open-Unmix и независимой спектральной оценке жужжания; около 10 секунд целевого аудио (+ контекст) отправляются в SCNet, если такие участки обнаружены. Полная SCNet никогда не подменяется быстрым режимом. Подавление речевого жужжания активировано, искажающая музыку подстановка фоновой текстуры отключена.

Результат **кодируется в само видео** как аудиодорожка с подавленными оригинальными диалогами, которая затем отправляется другим игрокам существующим механизмом отправки видеосцены. Гостям не требуется скачивать нейросеть. Редактор воспроизводит музыку при новых голосах, экспорт премьеры использует готовый очищенный фон вместе с записанными репликами. На сервер передаётся только признак cleaned, не исходный PCM.

Нажатие «Убрать голоса и продолжить» запускает подготовку до входа в комнату. Можно заранее нажать «Подготовить звук без голосов» для прослушивания, при необходимости отменить. Для исходно беззвучных мультфильмов предусмотрена отдельная возможность пропустить нейросеть. Если встроенный фильм недоступен из-за CORS, можно выбрать локальную копию. Эти три *нейронные модели* не зависят от свойств внешнего видеосервера.

Важно: спектральное разделение не гарантирует идеального удаления всех слов, не создаёт отсутствующие звуки заново, а точечная SCNet может не понадобиться, если остаточных проблемных мест не обнаружено. Качество проверить на реальном мультфильме.

# НЕ ТЕМ ГОЛОСОМ

Cooperative blind-dubbing studio in PocketWorks. Each player receives a role, records **selected** pieces of one common 30–90 second video with a three-second preroll, and hears only their own voice until the joint premiere.

- Quick PWA, responsive portrait/desktop editor, scene library and local video import.
- PocketNet is used for rooms, assignments, readiness and WebRTC signaling. Video and audio are transferred as binary data over peer-to-peer WebRTC channels, **not** stored in PocketNet (16 KB wire limit). WebRTC connectivity varies by NAT; no TURN relay is provisioned.
- Solo studio is fully usable offline with an imported file. Sample movies are licensed CC BY and stream from Wikimedia Commons/Blender when online, with attribution in the scene chooser. Keep original audio muted to avoid dialogue collisions.
- Audio stays private on the player's device until reveal. A local IndexedDB draft keeps the recorded fragments after reload. No server-side MP4 encoding; the premiere plays synchronized tracks in-browser.
- Self-contained app files live here. The immutable PocketNet module release and lock entry are infrastructure-required artifacts under pocketnet/.

Media licenses are not extended to user-uploaded footage; users must have rights to redistribute media they choose to share.

## Восстановление после отключений (1.8.1)

- Обрыв WebSocket не удаляет место участника: PocketNet сохраняет идентификатор, роль, текущую сцену и готовность. Подключение повторяется автоматически. При возобновлении WebRTC пересоздаются каналы медиа, а отсутствующие игроки отмечаются в комнате и на экране ожидания.
- Если вкладку перезагрузили, игра автоматически пытается вернуть прежнее место. Для вошедших через Pocket ID кратковременный идентификатор комнаты и токен сессии хранятся в браузерном localStorage, для гостей — только в sessionStorage (во избежание конфликтов между гостевыми вкладками).
- Комната без подключённых игроков сохраняется до 12 часов. Истёкшие и явно покинутые комнаты не восстанавливаются; игру можно покинуть обычной кнопкой.
- Реплики и исходник, уже сохранённые в IndexedDB, возвращаются при открытии записи или премьеры. Оригинальное видео ведущего записывается в локальный черновик ещё до начала игры; если браузер очистил хранилище, его можно выбрать повторно из комнаты.
- Потеря питания непосредственно во время незавершённой записи, очистка хранилища или поломка устройства не позволяют гарантировать восстановление последнего аудиофрагмента. Звуковые файлы по-прежнему не копируются на сервер. Если прямая WebRTC-передача недоступна, ограниченный запасной канал отправляет голос через PocketNet.

## Собственные видео

Загрузите MP4, MOV или WebM (до 512 МиБ на исходный файл при поддержке декодирования браузером). В экране подготовки задайте начало и длительность сцены (10–90 секунд). Мастерская умеет кодировать только тот фрагмент, который участвует в игре; можно изменить битрейт (пять ступеней) и предельную ширину кадра. После обработки доступно сравнение исходника и результата в одном видеоплеере. Единая кнопка «Использовать и продолжить» принимает обработанную сцену и открывает комнату. Исходный файл не изменяется и не загружается на сервер. Процесс кодирования идёт в реальном времени, при сворачивании экрана прерывается без замены оригинала.

Лимит для прямой WebRTC-передачи одного собственного видео — **96 МиБ**. Этого ограничения придерживаются выбор источника, подтверждение сцены, отправитель и получатель. Сжатие необязательно, если файл уже подходит. Результат кодируется с поддерживаемым браузером видеокодеком (WebM или MP4). Сохранение оригинальной звуковой дорожки зависит от поддержки браузером Web Audio/MediaRecorder; при отсутствии поддержки она может быть исключена. Без MediaRecorder/canvas.captureStream доступны только импорт и встроенная обрезка по таймлайну, без перекодирования. Видео гостям отправляется через WebRTC; для недоступного прямого соединения остаётся ручное подключение подходящего файла.

## Подготовка сцены (1.2.0)

На экране подготовки теперь одна визуальная кинолента: границы отрывка перетаскиваются независимо, выделенный диапазон можно двигать целиком, а кнопки «Начало здесь» и «Конец здесь» ставят маркеры по кадру исходного плеера. Допустимая длина — 10–90 секунд. Цифровые поля для ввода секунд скрыты: таймкоды показываются как ММ:СС, для точной регулировки доступны стрелки клавиатуры и Shift+стрелка.

На ПК экран компонуется в две колонки, с фиксированной панелью подтверждения. Видеопроигрыватель используется и для сравнения исходника и результата обработки. После обработки одна главная кнопка «Использовать и продолжить» одновременно принимает проверенный фрагмент и переходит к сценарию комнаты; если обработка не нужна, доступно «Продолжить с видео». Если собственный файл превышает лимит WebRTC, основное действие запускает обработку. При изменении границ или качества прежний результат аннулируется, чтобы он не был принят с устаревшими параметрами.

Тесты: `node --test apps/ne-tem-golosom/qa/*.test.mjs`. Браузерный сценарий с настоящим экспортом и снимками ПК/мобиля: `node apps/ne-tem-golosom/qa/video-journey.mjs` (требуется Playwright/Chromium). 

## Монтаж голоса (1.3.0)

Озвучка работает на отдельной модели `timeline-model.js`: у каждого локального фрагмента остаются `id`, `start`, `end`, `offset`, `owner` и неизменяемый `Blob`. Перезапись автоматически разделяет перекрытые старые фрагменты, не портя звуковые файлы и аудиосмещения.

- Выбор реплики — нажатием на клип. Удаляется **только выбранная** реплика; случайно удалить последний дубль невозможно.
- Undo/Redo — кнопки и `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` или `Ctrl+Y`; новая запись/удаление сбрасывает redo. Поддерживаются 40 шагов в каждую сторону.
- История хранится вместе с черновиком. При сериализации каждый аудио-Blob присутствует только один раз, даже если используется во многих снимках истории.
- IndexedDB v2 хранит исходное видео отдельно от метаданных дорожки: передвижение и удаление аудиофрагментов больше не переписывают тяжёлый видеофайл.
- Очередь транзакций записывает изменения последовательно. Выход из редактора и отправка готовности ждут завершения записи; при сбое сохранения проект не помечается готовым.
- Обновление таймкода меняет позицию курсора без пересоздания кнопок клипов. Это сохраняет фокус, выделение и будущую возможность точного drag-and-drop.

Старые черновики с полем `clips` загружаются без истории и автоматически переходят на новый формат при следующем успешном сохранении; встроенное видео из старого черновика также мигрирует в отдельное хранилище.

Проверки: `node --test apps/ne-tem-golosom/qa/*.test.mjs` и `node apps/ne-tem-golosom/qa/timeline-journey.mjs` для двух размеров экрана. Следующий этап — перемещение, подрезка и адресная перезапись реплик, а также мгновенная запись и отдельный трёхсекундный отсчёт.

## Монтаж реплик (1.4.0)

Редактор поддерживает обработку каждого голоса без повторной записи целой сцены:

- Нажатие на клип выделяет реплику. Перетаскивание за **центр** передвигает её во времени, за левую/правую ручку — подрезает начало или конец. Время голоса не растягивается, высота звука не изменяется.
- Реплики одной дорожки не могут перекрывать друг друга или выходить за границы сцены; минимальная длина клипа — 0,15 секунды. Если декодер знает полную длительность аудио, ранее отрезанный материал можно восстановить внутри доступной записи.
- Кнопки `−` и `+` переключают масштаб **1× / 2× / 4×**. Лента прокручивается по горизонтали, а страница игры не требует прокрутки. Работают мышь и сенсорные жесты.
- При выделении доступны «Перезаписать» и «Удалить». Перезапись стартует с начала **этой** реплики и автоматически останавливается у её конца, не трогая остальные записи. При досрочном завершении конец реплики сокращается.
- Большая кнопка **«Записать»** начинает запись сразу после получения разрешения на микрофон. Слева маленькая **«3»** запускает запись после отсчёта 3–2–1. Повторное нажатие на «3» отменяет отсчёт.
- `R` — мгновенная запись; `Shift+R` — с отсчётом. При выбранной реплике `Alt+←/→` сдвигает её на 0,1 секунды, `Alt+Shift+←/→` подрезает левый край, `Alt+Ctrl+←/→` подрезает правый. `Delete` удаляет выбранную реплику с подтверждением, Undo/Redo работают после всех правок.

Новые операции реализованы как чистые функции в `timeline-model.js`; каждый законченный жест — **одна** отменяемая операция. Черновики и протокол отправки голосов совместимы с 1.3.0, поскольку модель использует те же поля `start/end/offset/blob`.

Тесты модели: `node --test apps/ne-tem-golosom/qa/*.test.mjs`; браузерный сценарий: `node apps/ne-tem-golosom/qa/timeline-journey.mjs`. Визуальные проверки нужны и на телефоне, особенно для коротких (меньше секунды) реплик.

Этап 4 — оптимизация обработки исходных видео (версия 1.5.0). Следующий этап — экспорт общего результата в файл.

## Подготовка видео без лишнего кодирования (1.5.0)

Подготовка теперь начинается с **проверки лимита исходника**, а не с обязательного запуска кодировщика. Если файл целиком помещается в 96 МиБ (либо игра идёт в одиночном режиме), **«Продолжить с видео» работает сразу**: реплики отсчитываются от выбранного `start`, исходные закодированные байты остаются неизменными. Это не извлечение нового файла и не физическая обрезка медиаконтейнера; в кооперативном режиме целый исходный файл передаётся через WebRTC, поэтому предел 96 МиБ всё ещё действует для исходника.

Когда требуется более компактный файл, доступна локальная обработка только выбранного диапазона. В ней изменено следующее:

- При наличии `HTMLVideoElement.requestVideoFrameCallback` холст обновляется **при декодировании новых видеокадров**, а не на каждом кадре перерисовки страницы. Где поддерживается `CanvasCaptureMediaStreamTrack.requestFrame`, кодировщик получает именно новые кадры; в остальных браузерах автоматически используется прежний совместимый режим.
- Исходная звуковая дорожка **не обрабатывается по умолчанию**, поскольку общий просмотр озвучки её выключает. Можно явно включить опцию «Сохранить оригинальный звук при сжатии», если он понадобится внутри видеоматериала. Это снижает затраты ресурсов и размер файла, но не ускоряет сам таймер воспроизведения.
- Прогресс учитывает обработанные секунды видео; после начала воспроизведения показано приближённое оставшееся время. Достигнутые 100% отображаются только после окончания кодирования.
- Если исходник и все параметры экспорта (начало/длительность, качество, ширина, оригинальный звук) совпадают с уже обработанным результатом, готовый файл подставляется **мгновенно без повторного перекодирования**. В памяти удерживается только один последний подходящий результат; при выборе другого исходника или завершении работы он освобождается.
- Отмена прерывает ожидание загрузки/перемотки, завершаются дорожки и `AudioContext`. Предусмотрены сообщения для ошибки декодера, зависания воспроизведения и неподдерживаемого захвата кадров.

**Реальный предел:** когда файл превышает лимит передачи, используемый `MediaRecorder` всё ещё кодирует в ходе воспроизведения, и 60-секундная сцена обычно требует времени порядка её длительности. Более существенное ускорение для таких случаев потребует отдельного проверенного remux/WebCodecs-пути, которого в 1.5.0 нет. Оптимизация прежде всего устраняет ненужные повторные прогоны, экономит CPU и сообщает фактическое время.

Покрытие: `qa/media-lab.test.mjs` проверяет принятие/отклонение источника, ключ кеша, оценку звука и выбор способа кадров; `qa/video-journey.mjs` дополнительно проверяет отображение быстрой подготовки, повторное использование ранее сжатого файла, воспроизводимость результата и мобильную/настольную компоновку. Браузерный сценарий нужно исполнять в среде с Playwright/Chromium.

## Экспорт совместной премьеры (1.6.0)

Когда получены все дорожки игроков, на экране премьеры активируется **«Сохранить видео»**. Оно записывает локальный видеофайл с общей переозвучкой, а не только отдельные голосовые сообщения. Поддерживаемый браузером контейнер выбирается между MP4 и WebM; ссылка «Скачать ещё раз» остаётся доступной после завершения.

Обработка проходит без сервера: исходный фильм декодируется в отдельном скрытом видеоплеере, кадры записываются в Canvas/MediaRecorder, а голоса участников декодируются в Web Audio и смешиваются через общий MediaStreamAudioDestinationNode. Для каждого фрагмента учитываются `start`, `end` и `offset` — это те же данные, которые используются при премьере, включая ранее передвинутые и подрезанные реплики. Взаимное наложение голосов разных игроков допускается; при сведении применяется мягкая компрессия, чтобы меньше перегружать звук.

Оригинальный звук исходника по умолчанию отключён, как при обычной премьере. Его можно включить отдельным переключателем; тогда он добавляется тише голосовых записей.

Экспорт начинается только после получения **всех** ожидаемых голосов. Отображаются этап подготовки аудио и прогресс записи фильма; предусмотрена отмена. При сворачивании, переходе на другой экран и отмене освобождаются AudioContext, видеопоток, созданные аудиоисточники и временные URL. Ошибки декодирования реплик, кодека, блокировки аудиодвижка и преждевременного конца исходника показываются пользователю. Исходное видео и сохранённые голоса не перезаписываются.

Для видео из встроенной библиотеки браузер может запретить захват изображения, если сервер не отдаёт подходящие CORS-заголовки. В таком случае предлагается выбрать **локальную копию этого же фильма**: её длительность проверяется до использования, а файл применяется только для экспорта, без изменения комнаты и аудиодорожек.

**Технические ограничения:** MediaRecorder кодирует приблизительно в реальном времени; 60 секунд видео могут требовать не меньше минуты. Готовый WebM в зависимости от браузера может сначала сообщать неопределённую длительность; большинство проигрывателей воспроизводят его, но точная перемотка зависит от поддержки контейнера. Экспорт с оригинальным звуком зависит от браузерной реализации Web Audio и MediaRecorder. Загружать чужие фильмы разрешается только при наличии соответствующих прав.

Проверки:
- `node --test apps/ne-tem-golosom/qa/premiere-export.test.mjs` — временные границы, смешивание нескольких игроков, смещения и имена файлов.
- `node apps/ne-tem-golosom/qa/premiere-journey.mjs` — в Playwright/Chromium создаются реальные WebM и голосовые Blob, выполняется экспорт и проверяется открытие итогового файла и наличие аудиодорожки в поддерживаемых браузерах.
- `node --test apps/ne-tem-golosom/qa/*.test.mjs` — общие проверки игры.

Результат желательно дополнительно проверить с двумя настоящими участниками на устройствах: особенно на Safari/iOS и при слабом соединении WebRTC.

## Завершение UX и звуковая обратная связь (1.7.0)

В редакторе добавлен компактный **живой индикатор микрофона**: семь вертикальных делений отображают измеренную RMS-амплитуду сигнала через `AnalyserNode`. Шкала остаётся плоской в тишине и реагирует на голос, без синтетической случайной анимации; микрофон **не соединяется с колонками**. Измерение запускается при получении реального аудиопотока и останавливается при отмене отсчёта, завершении дубля, ошибке записи и выходе из проекта. При недоступности Web Audio запись продолжает работать без шкалы.

Во время записи показываются красный индикатор REC и текущая длительность дубля. Трёхсекундный отсчёт получил короткую анимацию и звуковые щелчки; общая настройка «Звуки» отключает эти сигналы. Пользователь может отключить визуальные движения через системную настройку `prefers-reduced-motion`.

Локальный черновик теперь имеет честные состояния **«Сохраняем…» / «Сохранено» / «Не сохранено»**. Сообщение о завершении появляется только после подтверждения IndexedDB и с учётом последней редакции — более старые асинхронные операции не перезаписывают новое состояние. Кнопка «Готово» блокируется на время подготовки и сохранения, предотвращая двойную отправку готовности.

В комнате виден отдельный статус PocketNet: подключение, онлайн или потеря связи. Фокус клавиатуры переводится на новый экран **только при смене раздела**, а не при каждом сетевом обновлении. Кнопки переключения звуков имеют `aria-pressed`.

Визуальная полировка сохраняет характер кинозала и физические органы управления: небольшие переходы, заметное выбранное положение реплики и соответствующие состоянию звуковые сигналы. Исключены декоративные анимации, которые могли вращать читаемый текст.

Проверки: `node --test apps/ne-tem-golosom/qa/studio-feedback.test.mjs` и обновлённый `qa/timeline-journey.mjs`. Полный регрессионный прогон браузера и многопользовательские тесты относятся к следующему этапу.


## Быстрая физическая обрезка MP4 (1.14.6)

Для локальных файлов **MP4 с H.264 (avc1) и AAC (mp4a)** мастерская сначала пытается собрать самостоятельный короткий MP4 из сжатых сэмплов. Она физически удаляет ненужные интервалы, в отличие от прежнего способа с ограничением воспроизведения. Ключевые кадры H.264 и временные таблицы MP4 пересобираются с поправкой на выбранное начало. Браузеру не требуется повторно декодировать и записывать каждый кадр.

- Быстрый путь действует при выборе **исходного звука** или **без звука** и настройках, сохраняющих исходное разрешение и высокий уровень качества. При отключении звука AAC-трек не включается.
- Для H.265/HEVC, WebM, MOV с нестандартным кодеком, фрагментированного MP4 или слишком крупного результата автоматически используется прежний `MediaRecorder`. В кооперативной комнате выход обязательно укладывается в 96 МиБ.
- **Нейросетевой режим** по-прежнему должен записать новую аудиодорожку. Поэтому его финальная сборка пока идёт в реальном времени; оптимизация MP4 без перекодирования не означает ускорения этого этапа.
- Файл-оригинал не изменяется. Пользователь видит результат и может сравнить его с исходником до подтверждения. Передача в комнату начинается только после подтверждения.
- Целиком переиспользовать без физической обрезки можно лишь исходник, чей выбранный диапазон совпадает с полной длительностью. Короткий выбранный участок больше не отправляет целый исходный фильм.

Проверки: `qa/mp4-fast-cut.test.mjs` генерирует реальные MP4 через FFmpeg, вырезает разные интервалы с H.264/AAC, в том числе B-кадры, проверяет длительность, число дорожек и декодирование. Если резак не поддерживает конкретный файл, он возвращает `null`; приложение переходит к обычному кодированию без потери исходника.


## Голоса, микрофон и синхронизация нейрофона (1.14.7)

- Каждая голосовая реплика может независимо усиливаться до **800% (8×)**. Черновики, Undo/Redo, отправка другим участникам и экспорт премьеры используют одну схему сохранения коэффициента. На выходе предпросмотра есть ограничитель пиков, поскольку при усилении выше 100% возможно цифровое перегружение.
- При каждой новой записи можно выбрать режим микрофона: **Без обработки** (по умолчанию; включает речь, дыхание, окружение и другие звуки) или **Шумоподавление** (браузер пытается убрать фон). Эхоподавление и автоматический усилитель запрашиваются отключёнными в обоих режимах. Выбор относится к следующей записи либо перезаписи выбранной реплики. Подавление шума, уже выполненное операционной системой при захвате, необратимо.
- Браузерное API `MediaTrackSettings` проверяется после захвата: при принудительном включении шумоподавления или недоступности выбранной обработки появляется предупреждение. Поддержка зависит от телефона, браузера и гарнитуры.
- При кодировании видео очищенная нейросетью звуковая дорожка теперь отслеживает **реальную позицию видеоплеера**. Запуск и возобновление аудио используют смещение от `scene.start`, небольшие отклонения корректируются частотой воспроизведения, а при скачке позиции дорожка перепривязывается к актуальному таймкоду. Пауза и возвращение на вкладку также перепривязывают звук.
- Уточнение: перемещение/подрезание голосовой реплики затрагивает только её `start/end/offset`. Таймлайн исходного или нейроочищенного фильма отдельно от реплик и не должен сдвигаться от их редактирования. Для уже подготовленного раньше видео исправление синхронизации требует повторного кодирования исходника.
- Автотесты: `qa/film-audio-sync.test.mjs` проверяет начальный сдвиг, накопление дрейфа, остановку и возобновление, `qa/clip-mix.test.mjs` — усиление и сохранение 8×, `qa/recording-audio.test.mjs` — режимы подавления.


## Раунды и быстрый экспорт премьеры (1.14.8)

- **Новая озвучка в той же PocketNet-комнате:** переход к следующему `round` сохраняет прежний черновик под старым ключом, очищает `localClips`, `remoteClips`, Undo/Redo и выделенную реплику, отменяет позднюю загрузку прошлого черновика. Для нового раунда записывается пустой черновик, чтобы старая запись не восстановилась из уже загрязнённого сохранения. Обновления присутствия и переподключения внутри одного раунда НЕ удаляют текущие реплики.
- **Защита передачи:** клиент и сервер дополнительно сверяют `meta.round` при отправке/получении WebRTC и PocketNet-relay. Голосовые файлы предыдущего раунда больше не принимаются, даже если видео и `mediaEpoch` не менялись.
- **Быстрый первый экспорт MP4:** при наличии `OfflineAudioContext`, WebCodecs `AudioEncoder`, подходящего H.264/AAC MP4 и совместимого AAC-LC профиля голоса сводятся офлайн, кодируется лишь новая аудиодорожка. Сжатые исходные видеосэмплы копируются без повторного кодирования. Такой экспорт может завершаться значительно быстрее времени сцены, но скорость зависит от устройства и эффектов.
- Для WebM, видео без AAC, встроенного URL, несовместимых или неподдерживаемых браузером MP4 используется прежний надёжный `MediaRecorder` (примерно в реальном времени). Если оптимизированный путь выдаёт ошибку, приложение возвращается к нему автоматически; пользовательский черновик не затрагивается.
- **Повторное сохранение без изменений:** хранится последний готовый файл, привязанный к объекту источника, раунду, участникам, таймлайнам, эффектам и флагу фонового звука. Повторное скачивание не кодирует видео заново. При смене раунда кеш удаляется.
- QA: `qa/round-isolation.test.mjs`, `qa/media-protocol.test.mjs`, `qa/pocketnet-server.test.mjs`, `qa/premiere-fast.test.mjs` (создание/декодирование реальных MP4 через FFmpeg).

Сохранение 30-секундного MP4 через быстрый путь не означает мгновенную работу с любыми файлами: особенно мобильный Safari и WebM могут требовать прежнего экспорта. Проверка реального ускорения проводится на конкретном браузере и видео.
