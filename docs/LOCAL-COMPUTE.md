# Pocket Works — домашний вычислительный runner

**Репозиторий:** https://github.com/JustSadSock/pocket-works (остаётся публичным).
**Назначение:** воспроизводимые тяжёлые тесты apps/living-history без доступа агента к личным файлам.
**Стоимость:** стандартные облачные Actions в публичном репозитории и self-hosted runner бесплатны; хранение артефактов сверх квоты может тарифицироваться.

## Важная граница безопасности

GitHub **не рекомендует** подключать self-hosted runners непосредственно к публичным репозиториям: автор внешнего pull request способен попытаться запустить вредоносный workflow. Ограничение запуска по автору Issue и по названию workflow **не устраняет риск на уровне репозитория**. Поэтому не запускайте runner в основной сессии Windows, в папке с личными файлами или с административными правами.

**Рекомендуется:** выделенная Ubuntu Linux VM на домашнем Windows-ПК (Hyper-V при наличии, VirtualBox или VMware), 8 виртуальных CPU, 12–16 ГБ RAM, 40+ ГБ диска, NAT-интернет. Отключите общие папки, передачу USB, общий буфер обмена и привилегированный доступ к основной системе. Не копируйте в VM пароли, SSH-ключи, авторизационные токены и личные файлы. Не подключайте runner к другим репозиториям. При подозрении на компрометацию удалите VM и перевыпустите токен runner.

Отдельный обычный пользователь Windows — **менее безопасная альтернатива**, не равнозначная VM.

## Установка — рекомендуемый вариант с Ubuntu VM

1. Установите VirtualBox (или используйте Hyper-V при наличии) на Windows 11.
2. Создайте Ubuntu 24.04 LTS VM с NAT, 8 vCPU, 12–16 ГБ RAM и 40+ ГБ диска. Убедитесь, что VM имеет доступ к github.com.
3. Откройте https://github.com/JustSadSock/pocket-works/settings/actions/runners → **New self-hosted runner** → **Linux / x64**.
4. Создайте в VM отдельную папку для runner, скачайте и распакуйте runner **точно командами, которые GitHub показывает на этой странице**. Не копируйте чужие токены и номера версий. Не используйте sudo для запуска jobs.
5. На шаге настройки выполните выданную GitHub команду ./config.sh с дополнительным аргументом **--labels pocketworks-compute**. Пример формы (не вставляйте текст-заглушку как настоящий токен):

~~~bash
./config.sh --url https://github.com/JustSadSock/pocket-works --token TOKEN_FROM_GITHUB --labels pocketworks-compute
~~~

6. При вопросе о runner name выберите, например, pw-home-vm. Другие настройки оставьте стандартными.
7. Запустите runner командой ./run.sh от обычного пользователя VM. Для первого теста пока оставьте терминал открытым.
8. В GitHub Settings → Actions → Runners проверьте статус **Idle** и наличие labels **self-hosted**, **Linux**, **X64**, **pocketworks-compute**.

**Если не хотите VM:** можно выбрать **Windows / x64** на том же экране, выполнить показанные GitHub команды скачивания в отдельной директории, затем:

~~~powershell
.\config.cmd --url https://github.com/JustSadSock/pocket-works --token TOKEN_FROM_GITHUB --labels pocketworks-compute
.\run.cmd
~~~

Этот Windows-вариант нельзя считать безопасным для основного домашнего ПК с личными данными. Установка runner как системной службы на основной Windows здесь не рекомендуется.

## Первый тест — через GitHub

1. Откройте https://github.com/JustSadSock/pocket-works/actions/workflows/local-compute.yml .
2. Нажмите **Run workflow**, выберите ветку main.
3. Выберите **regression** и нажмите зелёную кнопку запуска.
4. Наблюдайте в Actions: job перейдёт из Queued в In progress, когда VM runner находится в состоянии Idle.
5. После завершения скачайте артефакт **living-history-compute-...**. Внутри есть local-compute-output/run.json с итогом и временами выполнения.

Если job бесконечно остаётся Queued, проверьте в GitHub labels и состояние runner. Если ошибка **Node executable not found**, проверьте шаг setup-node, соединение с GitHub и свободное место на VM.

## Запуск от агента через GitHub Issue

В этом репозитории workflow слушает **только создание Issue** с точным заголовком:

~~~text
[compute] living-history
~~~

Автором Issue должен быть **JustSadSock** (реальное поле автора, а не текст в теле). Тело — JSON, без Markdown и команд.

Стандартная регрессия:

~~~json
{"profile":"regression"}
~~~

Независимые многолетние миры (каждый отдельным процессом, максимум четыре одновременно):

~~~json
{"profile":"audit","worlds":4,"years":50,"period":10}
~~~

Полная калибровка сценариев:

~~~json
{"profile":"calibration","scenario":"all"}
~~~

Допустимые значения:
- profile: regression, audit или calibration.
- audit: worlds от 1 до 8, years от 10 до 100, period от 1 до 20, years должен делиться на period.
- calibration: scenario normal, drought, isolated, uplands, all или century.
- Неизвестные поля и произвольные команды отклоняются.

Агент с доступом к GitHub Issue может создать такой Issue; workflow стартует при создании, если runner уже зарегистрирован. **Токены не нужны ни в теле Issue, ни в репозитории.** Issue публичный, не помещайте туда конфиденциальные данные.

Если при создании Issue через подключённое приложение GitHub его автором окажется бот, а не JustSadSock, защитная проверка правильно отклонит запуск. В таком случае используйте ручной Run workflow либо создавайте Issue из своего аккаунта. Не расширяйте разрешённый список авторов до всех пользователей ради обхода ограничения.

## Что делает workflow

1. Проверяет событие и автора до назначения задачи на self-hosted runner.
2. Из main извлекает фиксированный проверенный код без сохранения токена checkout в рабочей папке.
3. Ставит Node.js 22 и тестирует парсер запросов.
4. Выбирает только один из жёстко перечисленных профилей тестирования.
5. Для audit запускает несколько независимых процессов Node.js; каждый вычисляет мир со своим seed и сохраняет timeseries.csv, people.csv, results.json, REPORT.md.
6. Отправляет отчёты в GitHub Actions Artifacts; общий run.json содержит статусы и длительности.

Максимум одной активной задачи на уровне workflow concurrency; лимит одного выполнения — 120 минут. Следующие задания ставятся в очередь. Это **не** даёт агенту возможность запускать произвольный shell-код или управлять основным Windows.

Исходные тестовые данные и отчёты доступны в публичных логах и артефактах GitHub Actions. Артефакты сохраняются 7 дней; большие отчёты увеличивают занимаемое место.

## Проверки и отключение

Контроллер тестируется отдельно на стандартном GitHub-hosted Ubuntu runner при PR и изменениях main. Ни один PR workflow не использует домашний self-hosted runner.

Для прекращения работы остановите ./run.sh или .\run.cmd; затем при необходимости удалите runner в GitHub Settings → Actions → Runners. Компьютер и VM должны оставаться включёнными для выполнения очередных задач. Смена модели жизни или добавление новых сценариев требует отдельной разработки, но сам маршрут запуска не зависит от графики приложения.
