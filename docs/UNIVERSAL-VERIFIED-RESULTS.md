# Universal Verified Results — cross-commit proof pilot

This first expansion is deliberately non-authorizing. Banners production delivery stays unchanged. The pilot runs Axis Pals rules, Press zip-regression and FLICKYARD engine in network-disabled read-only containers from two immutable historical commits. Scope is the whole app, shared, scripts, package manifests, not a guessed import graph. Every mounted byte and executable bit is checked against Git, metadata normalized, and mount digests compared before/inside/after. No Git metadata or commit-specific CI environment is exposed to tests. The actual runtime image, configuration, Node binary, kernel and CPU are recorded. Both sides execute; successful complete TAP assertions are compared without timing. This is empirical evidence, not a general determinism guarantee. Browser, performance, install-dependent, external service and unknown tasks remain fresh. The existing Banners signed catalog is not retroactively broadened.

The positive real historical pair changes only an unrelated app; the negative pair changes scoped infrastructure. A subsequent phase must independently authenticate signed receipts, bind exact source and target mount/runtime proofs, rotate fresh canaries, and integrate the original mandatory plan gate before any reuse is enabled. No production admission is granted by this workflow.

The inventory is advisory and enumerates every configured application using the original QA planner. Install-free CPU tasks are only candidates, not authorized. Existing Banners Completion Lab is reported separately, and all other CPU, browser and visual tasks retain fresh execution. Per-app planner failures are explicitly listed; they never disappear as a successful empty plan.

## Signed receipt and gate pilot

The issuer reconstructs historical Git archives and raw test results in a separate job. Each receipt binds the original pair, task, immutable controller tree, run/attempt, mounted bytes, runtime, raw result and log digests, and seven-day expiry. Only protected main push or dispatch can obtain GitHub attestations; PR receipts are unsigned experimental outputs. A separate read-only gate downloads exact attempt artifacts, verifies all four attestations on main, reconstructs each receipt again, rejects missing and modified subjects, and checks complete matrix coverage. The required_gate job fails closed for the intended pilot. All tasks still execute fresh, and no change is made to the current production Universal QA gate. This is the necessary precondition for actual cross-commit delivery, not production reuse itself.

## Mixed delivery experiment

Pinned protected issuer run 46020376393, historical immutable target commits, independent signature verification and full reconstruction in both admission and final gate. Axis Pals may omit the fresh test command only on identical complete mounted and runtime fingerprints. Press always executes fresh as canary, FLICKYARD always executes fresh as negative control. Unknown, expired, unavailable or incompatible evidence fails to fresh. This experiment is not wired to the application production gate. Exact runtime mismatch is deliberately not relaxed. The small test tasks are proof cases, not an economic optimization claim.

## Economic preflight and observed runtime drift

The first authenticated mixed-delivery run 46020903299 verified all four subjects and passed all 62 fresh assertions. Axis Pals had identical mounted bytes but a different kernel and CPU fingerprint; no portability was authorized. The runtime differences and fresh assertion comparison are now emitted by the independent pilot gate. A comparison on another runner is observational, not a portable runtime guarantee.

The economic preflight is advisory and integrated into the original Universal QA plan; it cannot change the matrix or delivery route. The legacy aggregate additionally records only genuine fresh result durations in attempt-scoped telemetry, excluding verified or shadow records. Reuse candidates require at least three recent unique samples on both paths, conservative lower fresh cost and upper reuse cost, explicit discovery, authentication, preparation, verification, aggregation, transfer and amortized renewal costs; at least 30 seconds and 20 percent net savings. Missing or untrusted timing data remains fresh. Pilot tests are subsecond and therefore unsuitable economically, regardless of their technical equivalence. This is not yet a trusted ledger or a production admission rule. Sharded route and specialized Banners reuse are unchanged.

## Heavy simulation qualification

Four independent fresh executions compare Banners historical Completion Lab shard 0 and Crown current pinned balance shard 3 with deterministic controlled child commits that change only an unrelated documentation path. The gate reconstructs scoped archives and original simulation projections; scoped script mutation, missing artifacts and wrong attempt are negative controls. Runtime drift is recorded, not globally authorized. No production route or gameplay authorization is changed. Controlled commits are local Git objects, not application releases. This stage does not issue production receipts or skip expensive tests.
