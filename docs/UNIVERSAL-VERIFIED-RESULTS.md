# Universal Verified Results — cross-commit proof pilot

This first expansion is deliberately non-authorizing. Banners production delivery stays unchanged. The pilot runs Axis Pals rules, Press zip-regression and FLICKYARD engine in network-disabled read-only containers from two immutable historical commits. Scope is the whole app, shared, scripts, package manifests, not a guessed import graph. Every mounted byte and executable bit is checked against Git, metadata normalized, and mount digests compared before/inside/after. No Git metadata or commit-specific CI environment is exposed to tests. The actual runtime image, configuration, Node binary, kernel and CPU are recorded. Both sides execute; successful complete TAP assertions are compared without timing. This is empirical evidence, not a general determinism guarantee. Browser, performance, install-dependent, external service and unknown tasks remain fresh. The existing Banners signed catalog is not retroactively broadened.

The positive real historical pair changes only an unrelated app; the negative pair changes scoped infrastructure. A subsequent phase must independently authenticate signed receipts, bind exact source and target mount/runtime proofs, rotate fresh canaries, and integrate the original mandatory plan gate before any reuse is enabled. No production admission is granted by this workflow.

The inventory is advisory and enumerates every configured application using the original QA planner. Install-free CPU tasks are only candidates, not authorized. Existing Banners Completion Lab is reported separately, and all other CPU, browser and visual tasks retain fresh execution. Per-app planner failures are explicitly listed; they never disappear as a successful empty plan.

## Signed receipt and gate pilot

The issuer reconstructs historical Git archives and raw test results in a separate job. Each receipt binds the original pair, task, immutable controller tree, run/attempt, mounted bytes, runtime, raw result and log digests, and seven-day expiry. Only protected main push or dispatch can obtain GitHub attestations; PR receipts are unsigned experimental outputs. A separate read-only gate downloads exact attempt artifacts, verifies all four attestations on main, reconstructs each receipt again, rejects missing and modified subjects, and checks complete matrix coverage. The required_gate job fails closed for the intended pilot. All tasks still execute fresh, and no change is made to the current production Universal QA gate. This is the necessary precondition for actual cross-commit delivery, not production reuse itself.
