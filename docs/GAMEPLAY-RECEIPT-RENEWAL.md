# Renewable Banners gameplay evidence

The renewal controller resolves only the approved same-repository Banners of War PR #1355, or main after that PR merges. It freezes the candidate commit and tree once per run. The trusted controller is the exact workflow checkout. Fresh gameplay and performance execute in separate offline, read-only-input pinned containers, with full mount and environment fingerprints. The eight receipts are reconstructed from original phase evidence by an independent catalog job. Only a main push, schedule, or manual dispatch can attest the nine published JSON subjects (eight receipts plus catalog). PR validation cannot sign. The catalog is exact-source, exact-controller and exact-environment only, expires after seven days, and does not grant production admission. Changes to the audited scenario plan block issuance. Scheduled renewal runs every six hours; relevant main changes also trigger renewal. The first implementation does not deduplicate identical source runs, generalize to other apps, or automatically consume the catalog in production. Those are subsequent integration steps.

## Scheduled renewal deduplication

Only scheduled runs may skip issuance. The guard independently discovers and authenticates all nine signed subjects, reconstructs all eight original bundles, and requires exact candidate and controller commits and trees, the current plan and pinned runtime policy. It does not extend the original expiry; the receipts must have at least two of their original seven days remaining. A scheduled skip publishes only a decision report, never new receipts or attestations. A missing, stale, incompatible or unavailable catalog causes the original fresh matrix to run. Push and manual dispatch remain unconditional fresh renewal. Discovery scans up to 100 recent successful runs, cheaply excluding runs without a current-attempt unexpired catalog artifact before attempting at most eight actual catalog downloads. Scheduled deduplication also filters to the exact controller issuer. Metadata never authorizes reuse; nine signatures and eight original bundles remain mandatory. This permits up to five days between scheduled issuances on an unchanged source/controller, with a two-day expiry buffer. API errors and bounded lookback exhaustion cause fresh renewal. No delivery policy changes.

Discovery and scheduled decisions now publish observational lookup counters: eligible runs, issuer exclusions, metadata requests, absent/expired catalogs, and actual catalog downloads. These counters do not authorize reuse. The eight-candidate limit also stops metadata requests once exhausted.
