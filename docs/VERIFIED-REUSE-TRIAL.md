# Verified reuse trial

A separate read-only main-only trial uses the identical offline runner preparation as the independently executed and attested Axis Pals task. It authenticates a previous successful main run through GitHub API, attempt-specific artifact and GitHub attestation CLI. It validates the old receipt, current immutable checkout, ancestry, current measured mount, environment, exact task and scoped inputs. On any miss it executes the unchanged task. On a match the trial genuinely omits execution and records provenance, **not** a synthetic legacy success. The independent original execution and verification always run; trial parity requires the original task to succeed and exactly one fresh/historical trial outcome. No change to Universal QA, CI Gate or delivery-policy.json. No reuse of performance data.

The first merge changes scoped files, so a historical miss is expected. A later main workflow_dispatch with the same immutable checkout (or an unrelated documentation commit) can test a real hit if its measured environment is identical. Do not loosen environment equality to manufacture a hit. Trial output is non-authoritative and does not grant a production skip. The two heavy game shards have measured report repeatability but are not on main, and mix fresh performance metrics with gameplay calculations. They are not eligible for this pilot; separately audited execution and performance contracts are still required.

## Automatic exact-commit replay

After a successful main-only Verified Results Shadow run, a distinct read-only replay controller can consume that completed run's signed receipt. It requires the controller's own main checkout to equal the upstream SHA, verifies the exact attempt and attestation, and measures its own mount and environment using the same offline preparation. The admission target records the actual replay workflow/event and exact upstream run/attempt. A hit omits the experimental replay task; a miss executes the original task, never forges a fresh result. The upstream execution is independently verified. No production authorization. There is no workflow-dispatch write token or recursive trigger. Runs superseded by a different main SHA are deliberately skipped. Environment differences remain a real miss.
