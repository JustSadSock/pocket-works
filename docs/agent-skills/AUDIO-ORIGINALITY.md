# AUDIO ORIGINALITY — агентский стандарт Pocket Works

Обязательные правила проектирования звука для новых игр и существенных обновлений. Цель — свой звуковой почерк у **каждой** игры, а не одинаковые синусы, UI-пики и электронные клики по всему каталогу.

## Перед написанием звуков

В отдельном разделе `apps/<slug>/AUDIO.md` опиши:
1. **Материалы мира:** что соприкасается, движется и звучит (дерево, фетр, ткань, металл, мокрый камень, бумага, лёд и т. д.).
2. **Семейства действий:** установка/удар, перемещение/трение, вращение/щелчок, отрицательная обратная связь, успех/завершение, окружающий мир.
3. **Характер:** 3–5 слов (например: мягкий, низкий, бумажный, неспешный). Они должны зависеть от **игры**, не от Pocket Works.
4. **Запрещённые клише:** одинаковые генераторные `beep(freq)`, стоковый UI click на все действия, навязчивые ретрофутуристические бипы, несвязанные звуковые стили.

## Техническая реализация

- Используй браузерный Web Audio API для исходного, процедурного синтеза: буфер шума, bandpass/lowpass, несколько источников с независимыми амплитудными и частотными огибающими, контролируемые резонансы и зернистость.
- Чистый одиночный осциллятор допускается как **один слой** специфического звука, но не как универсальная замена всему саунд-дизайну.
- Для разного физического размера предмета меняй нижнюю частоту, длительность атаки и энергию шума, а не просто громкость.
- Повторные звуки должны иметь небольшой контролируемый разброс (2–5 % по высоте, 3–10 % по длительности, выбор 2–4 вариантов). Не используй большой случайный разброс, разрушающий узнаваемость.
- Звук запускается только после пользовательского жеста, никогда без разрешённого аудиоконтекста, всегда имеет доступное отключение. Учитывай iOS Safari, паузу при скрытии, `prefers-reduced-motion` и отсутствие Web Audio.
- По возможности не загружай внешние библиотечные звуки. При создании/использовании сэмплов храни исходники и лицензионные сведения внутри приложения; аудио должно быть доступно offline. Не завязывай приложение на платный API или внешний генератор.
- Никаких резких пиков и наложения 15 одинаковых кликов при серии быстрых действий. Используй лимит одновременных голосов и мягкое затухание.

## Пример реального саунд-дизайна

Уютная интерьерная диорама:
- **Предмет поставлен:** тихая тканевая атака + низкий «деревянный» импульс + затухание 150 мс.
- **Поворот мебели:** короткое трение с сухим механическим откликом.
- **Настольная лампа:** мягкий стеклянный резонанс, не цифровой тумблер.
- **Краска:** приглушённый шорох кисти, не сигнал подтверждения.
- **Ошибка размещения:** невысокий деревянный стук, не тревожный сигнал.

Средневековая тактическая игра — **другая** палитра: кожаный скрип, тяжёлая древесина, металл, ткань знамён. Воксельная головоломка — **третья** палитра: сухие короткие керамические импульсы с чётким ограниченным хвостом. Не копируй одну реализацию между играми.

## Приёмка

Проверь 10 последовательных действий с включённым звуком. Игрок должен различать **вслепую** хотя бы установку, отмену, ошибку и изменение состояния. При отключённом звуке игра обязана оставаться полностью понятной визуально. Протестируй обычную громкость телефона и маленькие динамики: глубина не должна превращаться в неслышный инфранизкий гул. Проверь наложения, быстрый повтор, возобновление iOS AudioContext и общую относительную громкость.

## Пример реализации в репозитории

`apps/komnatka/source/soundscape.js` и `apps/komnatka/AUDIO.md` (начиная с версии 0.1.2): ручной многослойный синтез с отдельной акустической структурой по событиям. Использовать как **принцип авторства**, а не копировать его тембры в другие игры.
