# Production gate readiness: renewable exact-tree admission

The current live experiment now checks out the actual GitHub merge commit for the approved Banners PR, not just its head. The admission logic permits an alternative commit only when GitHub identifies it as the exact current two-parent merge of that approved same-repository PR, the signed head is its second parent, the full Git tree is identical, and all existing source and controller mount, plan, signer and environment checks still pass. A differing merge tree does not qualify, even if app files appear similar.

Each job retains raw target manifest, plan, fresh phases and before/inside/after mount proofs. A separate aggregate runner independently re-authenticates the signed catalog and relevant receipt, reconstructs the phase outputs from raw evidence, verifies Git tree identities and checks the byte-exact projected files before emitting a gate candidate verdict. Every planned shard and the missing-evidence control must have an independently verified verdict. The rotating canary and all performance cases remain fresh. This is a pre-activation qualification; no mandatory QA task is skipped, all authorization flags remain false, and the existing production gate is unchanged. A later explicit delivery-route promotion must independently verify evidence on actual task checkouts and preserve the original plan. The strict full-tree rule intentionally rejects merges that include changes not present in the signed head.
