# Live CI Observatory and measured scheduling correction

The read-only controller runs on main after its own changes, daily at 04:23 UTC and on request. PRs run only regression contracts. It samples at most 12 recent completed runs per fixed workflow, includes only those updated in the last 24 hours, obtains all pages of the exact latest attempt's job metadata, and groups successful, failed and cancelled runs separately. It reports wall time, initial queue proxy, summed measured runner duration, missing metadata, CPU/browser shard timings and sample truncation. Reports are in the job summary and JSON/Markdown artifact, retained 14 days. It consumes no app artifacts, logs, secrets, or PR code on main. Estimates and actual observations are separate. No automated coverage reduction or authoritative timing claims.

Measured correction: Banners completion seed 0 ran 601161 and 593025 ms in the full repeatability audit (run 45717048670), while grouped CPU shards in run 45711361585 were cancelled after about 21 minutes. The eight completion seeds now get individual shards, using a conservative 15-minute scheduling estimate each. Crown balance seed 3 received a 20-minute estimate after the 936-second live measurement in 45710896020, so it is queued first; other balance seeds keep conservative isolation. Existing six CPU runner slots are unchanged. The original plan, task identities, delivery policy, evidence and mandatory checks are unchanged. Existing app branches must receive the updated infrastructure before their runs use the new scheduler. Compare subsequent completed live runs before claiming measured speedup.
