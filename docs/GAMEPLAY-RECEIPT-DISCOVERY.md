# Automatic gameplay receipt discovery

Universal QA now has a parallel, non-authorizing discovery job after its ordinary plan. It searches only for the planned Banners completion tasks, on the approved same-repository PR or the exact main checkout. It queries successful main renewal runs, filters stale/foreign/failed runs, selects the current candidate commit and independently checks source and issuer trees. It authenticates all nine JSON subjects with GitHub attestations and reconstructs all eight receipts from their original downloaded bundles. The complete verified payload is published separately from QA result artifacts. No historical record satisfies a production gate, and no QA task depends on the discovery job. A missing, expired or invalid catalog produces a fresh-fallback report; required direct and sharded QA remain unchanged.

A PR candidate HEAD and the actual merge checkout are distinct. Discovery records both; the next admission stage must independently verify the actual mounted inputs, controller and environment before using any receipt. No environment portability or production authorization is inherited. The live integration test waits for the first main renewal run as a test dependency, then discovers automatically without passing its run ID to the discovery implementation.
